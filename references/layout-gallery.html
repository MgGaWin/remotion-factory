Part 3 · 逐层深入模式

同一知识点，三帧讲完：概览 → 详解 → 深挖。像放大镜一样从全景到细节。

第一层 · 概览 — 一屏看完全部
2-1 简洁
RDD 五大核心特性
不可变 分区 惰性求值 持久化 容错
五个词，观众记住了。接下来逐个展开。
观众收获：知道"有哪些"
↓ ZOOM IN ↓
第二层 · 详解 — 每项一行解释
2-2 密集
RDD 五大核心特性
1
不可变 Immutable
创建后不能修改，每次转换生成新 RDD，保证一致性和容错性
2
分区 Partitioned
数据分布在集群多个节点上并行处理，分区数决定并行度
3
惰性求值 Lazy
Transformation 不立即执行，只在 Action 触发时计算，优化执行计划
4
持久化 Cacheable
可选择存储在内存或磁盘，重复使用的 RDD 缓存后避免重算
5
容错 Fault-Tolerant
通过 Lineage 血统信息重算丢失分区，无需数据复制
观众收获：知道"是什么"
↓ ZOOM IN · 挑一个点深入 ↓
第三层 · 深挖 — 单点展开：分区机制
2-3 深挖
深入理解分区
RDD 特性 #2
分区是 RDD 数据在集群中的物理分布方式。每个分区对应一个 Task，分区数 = 并行度。
分区策略
HashPartitioner
key.hashCode % numPartitions，最常用
RangePartitioner
按范围划分，适合有序数据
自定义 Partitioner
继承 Partitioner 类，按业务逻辑分区
数据分区示意
原始数据
→
P0 · Node 1
P1 · Node 2
P2 · Node 3
设置分区数
val rdd = sc.textFile("data.txt")
  .repartition(200)
rdd.partitions.length // 200
分区数 ≠ 越多越好
太少→并行度不够，太多→调度开销大

D4 · 左解释 + 右代码

左侧放文字解释、要点提示、关键参数（3-4 层信息），右侧放完整代码（10-15 行）。适合 API 用法、代码演示、技术概念配代码。

LangChain Agent 快速上手
Agent = LLM + Tools + Planning。LLM 自主决定调用哪个工具、传什么参数、何时停止。
核心概念
Tool Calling ReAct Memory Planning
关键参数
temperature: 0~1 控制创造性
max_iterations: 最大工具调用轮次
early_stopping: "force" 强制停止
verbose: True 打印推理过程
常见陷阱
✗ 工具描述不清晰 → LLM 乱调用
✗ 无 max_iterations → 无限循环
✗ 无 Memory → 多轮对话丢失上下文
agent_demo.py
from langchain_anthropic import ChatAnthropic
from langchain.agents import create_tool_calling_agent
from langchain_core.tools import tool

# 1. 定义工具
@tool
def search_db(query: str) -> str:
  """搜索用户数据库"""
  return db.search(query)

# 2. 初始化 LLM + Agent
llm = ChatAnthropic(model="claude-sonnet-4-6")
agent = create_tool_calling_agent(
  llm, tools=[search_db], prompt=_prompt
)

# 3. 执行
result = agent.invoke({
  "input": "查询张三的订单"
})
print(result["output"])

D6 · 问题 - 改进对比

Prompt Engineering 优化
✗ 常见错误写法
指令模糊："帮我写个东西"——无角色、无格式、无约束
缺少示例：没有 Few-shot，LLM 猜你想要什么格式
信息过载：一次塞 10 个要求，LLM 顾此失彼
无输出约束：不限长度/格式/语言，输出不可控
忽略角色设定：不说"你是谁"，LLM 用默认人格回答
输出质量
35%
✓ 优化后写法
角色+任务+格式："作为产品经理，写 PRD，Markdown 格式"
Few-shot 示例：给 2-3 个输入输出对，锚定输出格式
分步拆解：CoT 思维链，每步只做一件事
输出约束："用 JSON 格式，不超过 500 字，中文输出"
System Prompt 固化角色、知识边界、回答风格
输出质量
92%

设计规则

PPT 思维（要避免）
✗ 所有内容居中对称
✗ 标题永远在上方
✗ 字号统一无层次
✗ 填满整个画面
✗ 每屏结构相同
✗ 空白 = 浪费空间
视频帧思维（要做到）
✓ 不对称偏置构图
✓ 标题可以在下、在侧
✓ 字号有戏剧性级差（16px → 120px）
✓ 留白是设计元素
✓ 每屏有独特视觉焦点
✓ 简洁帧和密集帧交替
