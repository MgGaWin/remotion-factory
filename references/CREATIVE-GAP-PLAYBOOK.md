## 1. 场景规划闸门

写任何 Scene 组件前，先在 `outline.md` 或开发笔记中为每个场景补齐：

```markdown
- Scene 3: 机制解释（22s, ch1-3.wav）
  - 帧型：密集帧 D4 左解释+右代码
  - 观众任务：看懂参数如何影响结果
  - 视觉重音：Level 2 当前参数行高亮
  - 留存节拍：Reveal + Contrast（旧写法 vs 新写法）
  - 色彩策略：中性卡 + accent 左边框，不新增辅助色
  - 字幕安全：核心内容 y < 930，底部留 160px
```

**硬规则**：不要在编码阶段临时决定帧型、重音和卡片形态。先规划，再实现。

## 2. 简洁帧选择指南

简洁帧负责改变观众状态；密集帧负责交付信息。

| 口播信号 | 优先帧型 | 画面任务 | 推荐模板 |
|---|---|---|---|
| "先记住一句话"、"真正的问题是" | 简洁帧 | 制造停顿、建立预期、强化关键词 | 大字独白 / 偏置构图 / 暗色章节点 |
| "有三个原因"、"分成四步" | 密集帧 | 让结构完整可见，逐项揭示 | D3 编号列表 / D5 网格卡片 |
| "对比一下"、"改进前后" | 密集帧 | 把差异放在同一视野内 | D1 数据表格 / D6 问题-改进对比 |
| "这里很反直觉"、"注意这个细节" | 简洁帧 -> 密集帧 | 先打断，再解释 | 简洁悬念帧 -> D4 代码/解释 |
| "到这里可以得出结论" | 简洁帧或 Feature 暗卡 | 回收信息，让观众能复述 | 大字结论 / Feature 暗卡 |

### 比例和连用

- 单章约 40% 简洁帧、60% 密集帧。
- 不连续 2 帧简洁帧，除非第一帧是章节开场、第二帧是概念预告且总时长很短。
- 不连续 3 帧密集帧；第三个密集点前插入简洁过渡、对比帧或结论帧。
- 简洁帧不能只是空；必须承担悬念、转折、总结、喘息中的一个任务。

## 3. 视觉重音体系

同一帧最多一个主重音。重音强度要匹配口播强度。

| 等级 | 用途 | 允许手段 | 禁止手段 |
|---|---|---|---|
| Level 1 词级 | 关键词、参数名、术语 | accent 文本、下划线、色点 | 整句变色、整段加粗 |
| Level 2 项级 | 当前正在讲的列表项/代码行 | 左边框、编号圆点、当前行高亮 | 之前所有项永久高亮 |
| Level 3 区块级 | 一个区域比其他区域重要 | Oat 卡、浅 tint 提示、细边框 | 高饱和整块背景 |
| Level 4 帧级 | 核心结论、章节转折 | 简洁帧、暗色主题、Feature 暗卡 | 同章反复使用 Feature 暗卡 |
| Level 5 节奏级 | 情绪变化、段落换挡 | 明暗切换、留白、短暂停顿 | 无意义闪烁、持续运动 |

### 选择规则

- 口播只是解释：Level 0-1。
- 口播说"注意/关键/核心/陷阱"：Level 2-3。
- 口播给结论或转折：Level 4。
- 章节切换或情绪换挡：Level 5。

## 4. 留住观众策略

视频的注意力来自"下一秒有理由继续看"。

### 节拍模型

| 节拍 | 作用 | 常用画面 |
|---|---|---|
| Hook | 让观众进入问题 | 简洁帧、反差句、大数字 |
| Map | 告诉观众这段怎么走 | 简洁帧 + 3-5 个标签 |
| Reveal | 逐项交付信息 | 密集帧逐项淡入 |
| Contrast | 制造判断感 | 左右对比、前后对比、代码旧新对照 |
| Payoff | 让观众能复述 | 结论条、Feature 暗卡、金句帧 |

### 时间规则

- 开场 8 秒内：直接给问题、反差或承诺，不先铺背景。
- 每 20-35 秒：至少一次轻转折，如简洁帧、暗色帧、对比帧、代码运行结果、结论条。
- 每 60-90 秒：一句结构回收，说明刚解决了什么、下一段为什么重要。
- 结尾 12 秒：给压缩版答案，最后一帧应像可截图的结论。

## 5. 色彩用量规则

颜色是语法，不是装饰。

### 80 / 15 / 5

- 80%：中性色承载阅读（Ivory / Ink / Slate / Cloud）。
- 15%：Oat、浅 tint、细分割线组织区域。
- 5%：accent 和辅助色负责真正的注意力。

### 场景配色

| 场景类型 | 推荐配色 | 风险控制 |
|---|---|---|
| 普通解释 | Ivory 背景 + Ink 文本 + 细分割线 | 不让每张卡都变成不同颜色 |
| 分类并列 | 中性卡 + 小色点/标签区分 | 辅助色只标识类别，不做整块背景 |
| 提示/风险 | tint 浅底 + 左边框 | 不用高饱和红橙大面积警告框 |
| 核心结论 | 暗色场景或 Feature 暗卡 + accent | 每章最多 1-2 次，避免失重 |
| 代码/终端 | Terminal 卡 + 当前行高亮 | 不把整页改成赛博暗色 |

**同帧最多两种辅助色**：一个主 accent，一个语义辅助色。Feature 暗卡内通常只保留 accent。只使用当前颜色库里的既有 token，不新增 chart-yellow/purple 或 tint-yellow/purple。

## 6. 好坏对比审稿

| 审查项 | 坏画面特征 | 好画面特征 |
|---|---|---|
| 焦点 | 标题、图表、标签、数字同等强度 | 一眼知道主角，其他元素服务主角 |
| 信息量 | 把口播全文搬上屏 | 屏幕只放结构、关键词、证据和结论 |
| 颜色 | 高饱和背景、辅助色整块铺满 | 中性色为主，颜色只做语义标记 |
| 节奏 | 元素同时出现，或者一直跳动 | 跟随口播逐项揭示，出现后保持 |
| 安全区 | 内容压到底部，字幕遮住重点 | 核心内容在 y=930 以上，底部留 160px |
| 对比 | 只是左右摆两堆文字 | 差异项一一对齐，有明确判断 |

## 7. 质检清单

- [ ] 本章简洁帧约 40%，密集帧约 60%。
- [ ] 没有连续 2 帧简洁、连续 3 帧密集。
- [ ] 每个场景只有一个主视觉焦点。
- [ ] 每个场景能用一句话说清"观众任务"。
- [ ] 视觉重音与口播重音一致。
- [ ] 当前项高亮随口播切换，不永久堆叠。
- [ ] 每 20-35 秒出现一次轻转折。
- [ ] 每 60-90 秒有一句结构回收。
- [ ] 同帧最多两种辅助色。
- [ ] Feature 暗卡内只保留一种辅助色。
- [ ] 辅助色不做整块容器背景。
- [ ] 每个密集帧有底部结论条或可复述的收束句。
- [ ] 所有内容在 y=930 以上，底部为字幕预留至少 160px。
- [ ] 好坏对比类场景能指出具体差异，不只展示风格差异。
